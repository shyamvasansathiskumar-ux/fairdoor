    01 · The problem

    Per-IP limiting gets both wrong.

    Wrong 1

    It punishes the innocent.

    Hostels and campuses sit behind a few shared public IPs. 110 students on one IP look like one very busy client, so they get throttled together.

    hostelA · 1 IP
    Wrong 2

    It misses the attacker.

    A script spread across 20 IPs gets twenty times the budget. The limiter sees twenty polite clients.

    02 · The idea

    Three parts. Aimed at the deadline.

    None of them is new on its own. The combination, aimed at deadlines, is the point.

    1Fair queue

    Count per student, not per IP.

    Requests queue by signed-in identity and are served round-robin (deficit round robin, Shreedhar & Varghese, 1995). One request in flight per student. A flooder with one account gets one turn per round, however many IPs it uses.

    2Arrival stamp

    Judge the deadline on arrival, not on service.

    stamp = HMAC(key, student ‖ arrival_time ‖ SHA-256(submission))

    When the server is saturated it doesn't drop the request. It hands back a signed stamp, and the browser resubmits later. Binding the hash means nobody can keep editing after the deadline.

    3Explainable flags

    Every throttle has a reason on record.

    So when a student says "the portal ate my submission", an administrator can answer with evidence instead of guessing.

    ✓Result

    The flood can use idle capacity. It can't take a student's turn.

    0 / 300missed, under a 60 req/s flood

    Under FairDoor the attacker still gets about 49% of capacity, by design: round-robin is work-conserving, so spare turns go to whoever asks.

    06 · What it doesn't show (yet)

    A model is only as honest as its assumptions.

    1. One attacker identity. Fairness is only as strong as identity. Fifty stolen accounts get fifty turns. Real deployments need SSO and enrolment-linked accounts underneath.
    2. Stamps are free here. In reality, issuing and verifying one costs CPU, and a flood of stamp requests is its own load. Issuance needs a cheap path and its own limit.
    3. No network latency, no crashes, one endpoint.
    4. The arrival curve is assumed: exponential, skewed late. Real portal logs would replace it.

    Prior art

    • RainCheck Filter, Kung, Lee, Tseng, Hsiao et al., IEEE ICNP 2015: turned-away clients get timestamped "rain checks". FairDoor's stamp is a descendant, with the submission hash and deadline semantics added.
    • Deficit Round Robin, Shreedhar & Varghese, SIGCOMM 1995.
    • Cloudflare Waiting Room (FIFO and random queueing) and Fair-Drop (fair dropping under load).
